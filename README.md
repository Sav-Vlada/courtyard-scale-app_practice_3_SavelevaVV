# Дворовый масштаб · Васильевский остров

Статическое веб-приложение для интерактивной оценки восприятия масштаба и стилистической
неоднородности дворовой застройки Васильевского острова в Санкт-Петербурге. Пользователь
кликает на карте, приложение собирает здания в радиусе 100 м и рассчитывает метрики двора.
Режим «Что если» позволяет менять высоту и расстояние между зданиями и сразу видеть, как
меняется `ratio`, класс замкнутости и интерпретация.

Приложение не использует платные сервисы, LLM и серверную логику. Все расчёты детерминированы
и воспроизводимы. Фронтенд работает как набор статических файлов; нужны только локальные
GeoJSON-файлы и тайлы OpenStreetMap.

> Приложение показывает связь метрик застройки с восприятием масштаба и стилистической
> неоднородности. Это не оценка качества среды и не прогноз поведения. Выбор участка требует
> градостроительного обоснования.

## Возможности

- Клик по карте → маркер → карточка с метриками окружающей застройки.
- Опорные точки — заранее рассчитанная сетка 50 × 50 м с готовыми метриками.
- Режимы «Исходное состояние», «Сценарий» и «Изменение».
- Сценарий: высота 3–30 этажей и зазор 10–80 м, живой пересчёт.
- Пресеты «Как есть», «Уплотнение +5 этажей», «Расширение двора +10 м», сброс.
- Сохранение сценариев в `localStorage` и таблица сравнения.
- Таблица опорных точек: сортировка, фильтры, пагинация, экспорт CSV.
- Автоматический поиск без ИИ: топ-10 по `ratio`, перепад этажности ≥ 5, точки, где
  +5 этажей меняет класс, минимальное разнообразие стилей.
- Разрез «было → стало» и схематичная визуализация сценария на карте.

## Быстрый запуск

Из корня проекта:

```bash
python -m http.server 8000
```

Затем откройте <http://localhost:8000/app/>. Открывать `app/index.html` напрямую через
`file://` нельзя: браузер заблокирует загрузку GeoJSON.

Требования к просмотру: современный браузер и доступ к `tile.openstreetmap.org` для подложки.
Leaflet и Turf.js лежат локально в `app/vendor/`, поэтому остальная часть приложения работает
без CDN.

## Публикация на GitHub Pages

В проекте уже есть workflow `.github/workflows/deploy-pages.yml`. При каждом push в `main`
он собирает статическую версию сайта и публикует её в ветку `gh-pages`. Файл `.nojekyll`
отключает обработку Jekyll, чтобы GitHub Pages отдавал файлы как есть.

### Первое включение

1. Откройте репозиторий на GitHub: **Settings → Pages**.
2. В блоке **Build and deployment** выберите:
   - **Source**: `Deploy from a branch`;
   - **Branch**: `gh-pages`;
   - **Folder**: `/ (root)`.
3. Нажмите **Save**.
4. Дождитесь завершения workflow во вкладке **Actions** (обычно 1–3 минуты).

Приложение будет доступно по адресу:

**https://sav-vlada.github.io/courtyard-scale-app_practice_3_SavelevaVV/app/**

Важно: нужен путь `/app/` на конце. Корень репозитория не содержит `index.html`.

### Обновление сайта

После первого включения каждый push в `main` автоматически обновляет `gh-pages` и сайт.
Ручной запуск: **Actions → Deploy static app to GitHub Pages → Run workflow**.

Если workflow не может создать ветку `gh-pages`, проверьте
**Settings → Actions → General → Workflow permissions** и разрешите
**Read and write permissions**.

Вместо `gh-pages` можно выбрать публикацию напрямую из ветки `main` и папки `/ (root)`:
`.nojekyll` уже добавлен, поэтому сайт будет работать и без workflow. Но вариант с `gh-pages`
удобнее: ветка `main` остаётся чистой, а деплой выполняется отдельным действием.

## Подготовка данных

Установите зависимости:

```bash
pip install -r scripts/requirements.txt
```

Скачайте здания и пересоберите данные:

```bash
python scripts/prepare_data.py
```

Скрипт:

1. Загружает здания через Overpass API по bbox из `app/config.js`. Ответы кэшируются в
   `data/raw/`. При недоступности Overpass можно явно использовать OSM API 0.6:
   `python scripts/prepare_data.py --osm-api`. OSM API также применяется как автоматический
   резерв, если Overpass не ответил.
2. Фильтрует здания по полигону острова `data/island.geojson`.
3. Присваивает год постройки: сначала OSM (`building:year`, `start_date`, `building:year_built`,
   `built`), затем kontikimaps, если передана выгрузка.
4. Импортирует недостающие годы и этажность из kontikimaps (ODbL) и сопоставляет контуры
   по расстоянию (≤ 15 м) и отношению площадей (0.35–2.8). Контуры kontikimaps приводятся
   к той же локальной метрической проекции, что и здания OSM.
5. Считает высоту, этажность, соседей, зазоры и `ratio` для каждого здания.
6. Строит сетку опорных точек 50 × 50 м и считает для них все метрики, включая сценарий
   «+5 этажей».
7. Записывает `buildings.geojson`, `reference_points.geojson` и `metadata.json`.

Для kontikimaps нужна выгрузка `HOITH_database_231118.gpkg` (версия 18.11.2023, около 1.8 ГБ),
скачанная с <https://kontikimaps.ru/how-old/cities250/datasets>:

```bash
python scripts/prepare_data.py \
  --kontiki-gpkg "C:/path/to/HOITH_database_231118.gpkg"
```

Без `--kontiki-gpkg` приложение продолжит работать, но годы будут только из OSM. Кэш
`data/raw/kontiki_buildings.geojson` создаётся один раз; для повторного импорта используйте
`--refresh-kontiki`.

Полезные параметры:

| Параметр | Назначение |
|---|---|
| `--bbox W,S,E,N` | заменить область исследования |
| `--chunks N` | число частей по каждой оси для Overpass (по умолчанию 4) |
| `--refresh-osm` | перекачать здания |
| `--refresh-island` | перезапросить границу острова |
| `--no-island-filter` | не фильтровать здания полигоном |
| `--no-kontiki` | не использовать kontikimaps |
| `--skip-reference` | не строить опорные точки |
| `--limit-buildings N` | ограничить число зданий для отладки |

При замене bbox обновите `studyArea.bbox` и `studyArea.origin` в `app/config.js`, затем
пересоберите данные. `origin` — центр области в WGS84; от него строится локальная
равнопромежуточная проекция, общая для Python и JavaScript.

## Методика

### Высота и этажность

- Если у здания есть тег `height`, используется он (метры).
- Иначе высота = `building:levels × 3.3`.
- Пропущенная этажность восстанавливается медианой по ячейке 500 × 500 м (при ≥ 8 зданиях),
  иначе медианой по району.
- Источники этажности фиксируются в `levels_source`: `osm`, `height`, `imputed_cell`,
  `imputed_district`.

### Соседи здания

Для каждого здания ищутся до 5 ближайших зданий в радиусе 100 м. Расстояние считается между
полигонами, а не между центрами. В свойствах здания сохраняются:

- `level_difference` — максимальная этажность соседей минус этажность здания;
- `nearest_distance` — расстояние до ближайшего соседа;
- `ratio = height / nearest_distance`;
- `neighbor_count` — сколько соседей попало в радиус.

### Метрики двора (точки клика)

Двор — это область в радиусе 100 м от точки. Учитываются здания, контур которых удалён от
точки не более чем на 100 м. Для выбранных зданий рассчитываются:

| Метрика | Определение |
|---|---|
| `avg_height` | средняя высота, м |
| `max_height`, `min_height` | максимум и минимум высоты, м |
| `level_range` | максимальная этажность минус минимальная |
| `min_gap` | минимальный положительный зазор между контурами |
| `avg_gap` | среднее по зданиям ближайших положительных зазоров |
| `ratio` | `avg_height / min_gap` |
| `style_diversity` | число различных известных стилей |
| `dominant_style` | стиль с долей ≥ 50% и строго большей, чем у второго |

Пары контуров ближе 1.0 м считаются соприкасающимися (стены по меже) и не образуют
положительный зазор. Если валидного зазора нет или зданий меньше двух, класс —
«Недостаточно данных».

### Классы замкнутости

| Класс | Условие |
|---|---|
| Открытый, слабо замкнутый двор | `ratio < 0.3` |
| Умеренно замкнутый двор | `0.3 ≤ ratio < 1.0` |
| Замкнутый двор (колодец) | `ratio ≥ 1.0` |
| Недостаточно данных | нет валидного зазора или меньше двух зданий |

Дополнительно перепад этажности ≥ 3 помечается как визуальный контраст силуэта.

### Стили и стилистическая неоднородность

Стиль определяется по году постройки и периодам из `app/config.js`:

| Период | Годы |
|---|---|
| Ранее барокко | 1703–1739 |
| Высокое барокко | 1740–1759 |
| Ранний классицизм | 1760–1779 |
| Строгий классицизм | 1780–1800 |
| Высокий классицизм | 1801–1809 |
| Поздний классицизм (ампир) | 1810–1830 |
| Эклектика (историцизм) | 1831–1899 |
| Модерн | 1900–1905 |
| Неоклассицизм | 1905–1919 |
| Авангард | 1920–1935 |
| От неоклассики к функциональной архитектуре | 1935–1989 |
| Архитектура конца XX – начала XXI века | 1990–2010 |
| Современная архитектура | 2011–2026 |

На границах 1905 и 1935 гг. выбирается более поздний период. Год вне 1703–2026 даёт
«неизвестно». `style_diversity` не учитывает «неизвестно»; доля неизвестных годов
показывается отдельно и предупреждает, если превышает 50%.

Интерпретация:

- нет стиля с долей ≥ 50% → положительная стилистическая неоднородность;
- есть доминирующий стиль → угроза гомогенности;
- отдельно отмечается угроза монотонности, если ≥ 50% зданий относятся к периодам
  1935–1989 или 2011–2026.

### Сценарий «Что если»

Сценарий стартует от реальных значений выбранной точки. Ползунки задают этажность и зазор;
высота пересчитывается как `этажи × 3.3`, `ratio` — как `высота / зазор`. Класс определяется
по тем же порогам. На карте исходные здания показываются полупрозрачно, сценарий — контурами;
разрез «было → стало» показывает высоту и зазор в масштабе. Геометрия зданий не
перестраивается — это параметрическая, а не проектная модель.

Предрасчитанный сценарий `+5 этажей` в таблице и поиске использует
`avg_height + 5 × 3.3` при неизменном `min_gap`.

### Опорные точки

Сетка 50 × 50 м внутри полигона острова. Точки внутри зданий и точки без валидного зазора
исключаются. Каждая точка хранит все метрики, класс, доминирующий стиль и результат
сценария `+5 этажей`.

## Проверка данных

```bash
python scripts/validate_data.py
```

Скрипт пересчитывает метрики контрольных зданий и опорных точек по контурам из
`buildings.geojson` и сверяет их с сохранёнными значениями. Проверка завершается сообщением
«Все проверки пройдены», если расхождения отсутствуют.

## Экспорт CSV

Кнопка «Экспорт CSV» выгружает отфильтрованные и отсортированные строки таблицы, а не только
текущую страницу. Формат: `;`-разделитель, UTF-8 с BOM, десятичная точка. Файл называется
`dvory_vasilievsky_ГГГГ-ММ-ДД.csv`.

## Ограничения

- Год постройки в OSM и kontikimaps может отсутствовать, быть приблизительным или относиться
  к реконструкции.
- Стиль — укрупнённая периодизация по году, а не атрибуция памятника архитектуры.
- Зазор между контурами не равен субъективной ширине двора и не учитывает ограды,
  растительность и рельеф.
- Сценарий меняет только два параметра и не является проектом застройки.
- Результаты не оценивают качество среды, не прогнозируют поведение и не заменяют
  градостроительное обоснование.
